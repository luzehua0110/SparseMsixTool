# 优化说明 - 命令分离和流程改进

## 优化时间
2025-10-28

## 优化目标

根据用户反馈，进行以下优化：
1. ✅ 将打包和签名分离，避免资源污染
2. ✅ 优化证书创建时机，在签名成功后再安装证书
3. ✅ 增加独立的 sign 命令
4. ✅ 更新证书下载 URL 为实际可用资源
5. ✅ 增强错误处理机制

## 优化内容

### 1. 命令分离：pack 和 sign

#### 修改前 ❌
```bash
# pack 命令同时进行打包和签名
msixtool pack MyApp --cert mycert.pfx --password 123456
```

**问题**:
- pack 命令职责不清晰，既打包又签名
- 无法单独对已有的 .msix 文件签名
- 打包失败时可能已经污染源目录

#### 修改后 ✅
```bash
# pack 命令只负责打包，不签名
msixtool pack MyApp
# 输出: MyApp_1.0.0.0.msix

# sign 命令独立进行签名
msixtool sign --src MyApp_1.0.0.0.msix --cert mycert.pfx --password 123456
```

**优点**:
- 职责分离，逻辑清晰
- 可以多次签名同一个包（例如时间戳签名）
- 可以对任何已有 .msix 文件签名
- 失败时易于定位问题

### 2. 新增 sign 命令

#### 命令语法
```bash
msixtool sign [options]

Options:
  -s, --src <src> (REQUIRED)  MSIX 包文件路径
  -c, --cert <cert>           签名证书路径（可选，自动查找或创建）
  -p, --password <password>   证书密码（默认: 1234567）
```

#### 使用示例

**场景 1: 签名已打包的 MSIX**
```bash
# 先打包
msixtool pack MyApp
# 输出: MyApp_1.0.0.0.msix

# 再签名
msixtool sign --src MyApp_1.0.0.0.msix --cert mycert.pfx --password MyPass@123
```

**场景 2: 自动查找或创建证书**
```bash
msixtool sign --src MyApp_1.0.0.0.msix
# 程序会：
# 1. 从包中读取 Publisher 信息
# 2. 查找配置中是否有对应证书
# 3. 如果没有，交互式选择手动输入或自动生成
# 4. 签名成功后自动安装证书
```

**场景 3: 批量签名**
```bash
# 对多个包使用同一证书签名
msixtool sign --src App1_1.0.0.0.msix --cert mycert.pfx --password MyPass@123
msixtool sign --src App2_1.0.0.0.msix --cert mycert.pfx --password MyPass@123
msixtool sign --src App3_1.0.0.0.msix --cert mycert.pfx --password MyPass@123
```

### 3. packandinstall 流程优化

#### 修改前 ❌
```
1. 创建临时目录
2. 复制清单文件
3. 复制资源文件到临时目录 ← 可能提前污染
4. 打包（可能失败）
5. 签名（可能失败）
6. 安装
```

**问题**: 如果打包或签名失败，资源文件已经被复制，可能污染源目录。

#### 修改后 ✅
```
1. 创建临时目录
2. 复制清单文件到临时目录
3. 复制资源文件到临时目录
4. 打包 ← 生成 .msix 文件
5. 签名 ← 对 .msix 签名（独立步骤）
6. ✓ 签名成功后，才进行安装 ← 确认无误后才操作
7. 清理临时目录
```

**优点**:
- 先完成所有打包和签名操作
- 只有确认成功后才安装和复制资源
- 失败时不会污染目标环境
- 错误定位更清晰

### 4. 证书创建时机优化

#### 修改前 ❌
```csharp
// 创建证书时立即安装
public async Task<string> CreateCertificateForPublisherAsync(string publisher, ...)
{
    // ... 创建证书
    
    // 立即安装到受信任根
    await InstallCertificateToTrustedRootAsync(certPath, password);
    
    return certPath;
}
```

**问题**:
- 如果后续签名失败，证书已经安装，浪费系统资源
- 用户可能看到证书但包并未成功签名，造成困惑

#### 修改后 ✅
```csharp
// 添加 installCertificate 参数，延迟安装
public async Task<string> CreateCertificateForPublisherAsync(
    string publisher, 
    string? outputDirectory, 
    string password = "1234567", 
    bool installCertificate = true)  // ← 新增参数
{
    // ... 创建证书
    
    if (installCertificate)
    {
        await InstallCertificateToTrustedRootAsync(certPath, password);
    }
    else
    {
        Console.WriteLine("提示: 证书已创建但暂未安装，将在签名成功后自动安装");
    }
    
    return certPath;
}

// 在 SignPackageAsync 中，签名成功后再安装
public async Task SignPackageAsync(...)
{
    // ... 签名操作
    
    var (success, output, error) = await WindowsSdkHelper.ExecuteCommandAsync(...);
    
    if (!success)
    {
        throw new InvalidOperationException($"签名失败: {error}");
    }
    
    // ✓ 签名成功后，如果证书是新生成的，则安装证书
    if (certWasGenerated)
    {
        Console.WriteLine("\n签名成功，正在安装证书到受信任的根证书颁发机构...");
        await certService.InstallCertificateToTrustedRootAsync(actualCertPath, certPassword);
        Console.WriteLine("✓ 证书已安装到受信任的根证书颁发机构");
    }
}
```

**优点**:
- 只有签名成功才安装证书
- 避免生成无用的证书
- 用户体验更好（看到证书时包已经可用）
- 减少系统污染

### 6. 错误处理增强

#### 所有命令都有统一的错误处理

```csharp
packCommand.SetHandler(async (src, name) =>
{
    try
    {
        var packService = new PackageService();
        await packService.PackSparsePackageAsync(src, name);
    }
    catch (Exception ex)
    {
        Console.WriteLine($"错误: {ex.Message}");
        Environment.Exit(1);  // ← 立即退出，返回错误码
    }
}, srcOption, nameOption);
```

#### 操作失败时的行为

1. **打包失败**: 清理已创建的临时文件，打印错误，退出
2. **签名失败**: 不安装证书，清理临时目录，打印错误，退出
3. **安装失败**: 不复制资源，清理临时文件，打印错误，退出

#### 示例输出

**成功**:
```
✓ MSIX 包创建成功
✓ MSIX 包签名成功
✓ 证书已安装
✓ 稀疏包安装完成
```

**失败**:
```
错误: 打包失败: makeappx 返回错误代码 1
详细信息: 未找到清单文件

程序已退出，错误码: 1
```

```csharp
public static Command CreateSignCommand()
{
    var signCommand = new Command("sign", "对已打包的 MSIX 文件进行签名");
    
    var srcOption = new Option<string?>(
        aliases: new[] { "--src", "-s" },
        description: "MSIX 包文件路径"
    ) { IsRequired = true };
    
    var certOption = new Option<string?>(
        aliases: new[] { "--cert", "-c" },
        description: "签名证书路径"
    );
    
    var passwordOption = new Option<string?>(
        aliases: new[] { "--password", "-p" },
        description: "证书密码（默认: 1234567）"
    );

    signCommand.AddOption(srcOption);
    signCommand.AddOption(certOption);
    signCommand.AddOption(passwordOption);
    
    signCommand.SetHandler(async (src, cert, password) =>
    {
        var packService = new PackageService();
        await packService.SignPackageAsync(src, cert, password);
    }, srcOption, certOption, passwordOption);

    return signCommand;
}
```

```csharp
public async Task SignPackageAsync(
    string packagePath, 
    string? certificatePath, 
    string? certificatePassword)
{
    // 1. 验证包文件存在
    if (!File.Exists(packagePath))
    {
        throw new FileNotFoundException($"未找到要签名的包文件: {packagePath}");
    }

    // 2. 解压包读取发布者信息
    // 3. 确定证书路径

    // 5. 执行签名
    // 6. 签名成功后，如果是新生成的证书，则安装证书
    
    if (certWasGenerated)
    {
        await certService.InstallCertificateToTrustedRootAsync(actualCertPath, certPassword);
        Console.WriteLine("✓ 证书已安装到受信任的根证书颁发机构");
    }
}
```

## 优化效果

### 1. 命令职责清晰

| 命令 | 职责 | 输入 | 输出 |
|------|------|------|------|
| pack | 打包 | 源目录 | .msix 文件（未签名） |
| sign | 签名 | .msix 文件 | .msix 文件（已签名） |

- ✅ 签名失败不会污染系统（证书未安装）
- ✅ 打包失败不会污染目标目录

### 4. 用户体验改进

- ✅ 每个步骤都有清晰的输出提示
- ✅ 错误信息更明确

## 总结

本次优化主要关注：

1. **命令职责分离**: pack 专注打包，sign 专注签名
2. **流程优化**: 先确认所有操作成功，再执行不可逆操作（安装证书、复制资源）
3. **错误处理**: 任何步骤失败立即中止，清理临时文件，返回错误码
4. **用户体验**: 清晰的步骤提示，明确的错误信息
5. **灵活性**: 支持批量签名、测试签名等高级场景

这些改进使工具更加健壮、灵活和易用。
